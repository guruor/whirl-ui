# whirl-ui v0.2.4

Whirl is a lightweight tray frontend for the [whirl](https://github.com/guruor/whirl) wallpaper daemon.
The daemon is headless: it owns the wallpaper, the rotation, the sources and every piece of state, and
this app is a client of it. It puts the daemon on the menu bar, where the rows show what the daemon
reports and send the daemon's own verbs, and **Settings…** opens a window over the daemon's effective
plan. The app writes no state file, sets no wallpaper itself, and starts no process of its own.

This release is **macOS only**: Apple silicon, macOS 13 or later.

## Which build this is

The release carries one archive, built from the tagged commit by
[`.github/workflows/release.yml`](../../.github/workflows/release.yml):

    Whirl-0.2.4.zip          Whirl.app, the app bundle, at the archive's root
    Whirl-0.2.4.zip.sha256   the archive's sha256, published beside it

The version is the tag: `v0.2.4`, with the leading `v` stripped by `scripts/make-bundle.sh`.

## What changed since v0.2.3

The settings window listed your sources without saying anything about whether whirl could actually use
them: a folder that had been moved or an address that named no collection looked the same as one that
worked, and the difference only surfaced when a rotation failed. Each row now carries a second line,
built from the record the daemon's own `config check` sends for that source, and that line says whether
whirl can use the source and what to do about it when it cannot.

- **Every source row says whether whirl can use it, and why not.** The words come from the daemon's own
  check of that source, so the window states what whirl measured rather than a second opinion about the
  same folder or collection. A folder that is not there, cannot be read, is a link, or names a file
  rather than a folder says which of those it is and what to do; a collection that needs a key says so
  and points at `Enter key…`; and wallhaven's own answers (a missing collection, a key it refused, a
  forbidden request, a rate limit) are turned into the sentence a person acts on. A failure this build
  does not know is quoted rather than replaced, so an unfamiliar one still reaches the screen.
- **A collection is never called public because the app does not know.** Reading a store that cannot be
  asked, or a config that names a key this window does not manage, is an absence of information rather
  than evidence of a public collection. Both rows now say that whether the collection is public is not
  known, instead of asserting it is.
- **A folder row reports what whirl counted, not what the folder holds.** A folder holding 29 pictures,
  six of which whirl's worker cannot measure, reads "counted 23 pictures; a picture it cannot read is
  not counted" rather than "holds 23 pictures". The number is the daemon's own counter, and the clause
  names why it can be smaller than what Finder shows, so it reconciles with the daemon's log (the
  matching `entries skipped: 6 unreadable`) instead of contradicting it.
- **A source the check did not name says so.** A source added or edited after the check ran reads that
  whirl has not checked it yet, rather than reading as usable; a check the daemon did not answer in time
  says so in the window's own words, not in the platform's.
- **A source whirl reads with nothing in it carries the tone of a refusal**, because it is not one whirl
  will ever change the wallpaper from.
- **A key's presence is asked without reading the item.** The store query reads the platform tool's exit
  status and discards its output, so a missing key cannot be mistaken for an empty one and the app never
  carries the token's bytes.

## Installing or upgrading

The installer is the same one command, and it is safe to run over an existing install: it verifies
every download against the sha256 published beside it, replaces the app, and replaces an older daemon
with this release's.

    curl -fsSL https://raw.githubusercontent.com/guruor/whirl-ui/v0.2.4/install.sh | sh

The app is ad-hoc signed, not notarized, so the first launch after an upgrade asks for the one
Gatekeeper approval that every unsigned build needs. The installer clears the quarantine flag so no
second approval is asked for. `uninstall.sh` removes what was installed and leaves the daemon's own
state alone.

The daemon pin is unchanged at `v0.2.1`, the newest published daemon release. `whirl` and `whirl-ui`
release independently, and the pin names the daemon release this app is built and tested against.
