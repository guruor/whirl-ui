# whirl-ui v0.2.3

Whirl is a lightweight tray frontend for the [whirl](https://github.com/guruor/whirl) wallpaper daemon.
The daemon is headless: it owns the wallpaper, the rotation, the sources and every piece of state, and
this app is a client of it. It puts the daemon on the menu bar, where the rows show what the daemon
reports and send the daemon's own verbs, and **Settings…** opens a window over the daemon's effective
plan. The app writes no state file, sets no wallpaper itself, and starts no process of its own.

This release is **macOS only**: Apple silicon, macOS 13 or later.

## Which build this is

The release carries one archive, built from the tagged commit by
[`.github/workflows/release.yml`](../../.github/workflows/release.yml):

    Whirl-0.2.3.zip          Whirl.app, the app bundle, at the archive's root
    Whirl-0.2.3.zip.sha256   the archive's sha256, published beside it

The version is the tag: `v0.2.3`, with the leading `v` stripped by `scripts/make-bundle.sh`.

## What changed since v0.2.2

The settings window's App pane described two different things at once, and the one control on it
changed the very state the pane was reporting. It is now two panes, each with a single subject, and the
app asks the daemon's own command for the parts of the lifecycle it used to leave to the installer.

- **Background Helper.** The part of Whirl that keeps running after you close the Control Panel, and
  changes your wallpaper on its own, on the schedule you set under Rotation. Its one switch reads
  `whirl daemon status` when the pane opens and when the window is focused, never from a cache: on for
  a running helper, on with a `Start now` step when the helper is loaded but stopped, off when there is
  no helper at all, and a disabled switch quoting whirl's own sentence for anything else. `Launch at
  login` runs `whirl daemon install` or `whirl daemon uninstall`, and `Start now` runs `whirl daemon
  start`. There is no permanent Start, Stop or Restart, and a pause stays a Rotation setting. Whirl's
  own paths and the app's rule about the daemon (it never writes a unit and never starts a process of
  its own) sit in two collapsed groups, so nothing on the pane's main surface names the machinery.
- **Control Panel.** This window itself: where you set Whirl up. Its own `Open Whirl at login` row opens
  the window at login, and its line says in plain words that the Background Helper is what changes the
  wallpaper, so leaving the Control Panel closed costs almost nothing. The menu bar icon exists exactly
  while the Control Panel runs, and there is no separate control over it.
- **Remove Whirl completely**, in About. It runs `whirl daemon uninstall` and forgets this app's install
  record, then says the app itself is removed by hand, with the one route for the platform you are on.
  It never writes into an installed location.
- **The app asks the daemon for the two verbs it was missing.** `install` and `uninstall` now reach
  `whirl daemon`, and the first run installs the login unit rather than starting a daemon, so
  "installed" and "comes back at login" are one action. The decision is recorded on every path,
  including one that found a daemon already running, so turning the background off is not undone behind
  your back. The app still writes no unit file and starts no process of its own.
- **A whirl command that never answers no longer freezes the window.** Both of the app's waits on a
  daemon command are bounded. On expiry the app ends its own child and prints its own sentence saying
  the daemon did not answer, instead of waiting forever.
- **Startup is set outside the installer, and the login unit is stopped before its binary is deleted.**
  `install.sh` places the binaries and no longer installs a login unit on a plain run; a headless or
  provisioning run asks for it with `WHIRL_UNIT=install`. `uninstall.sh` asks `whirl daemon uninstall`
  while the binary the unit runs is still in place, and if whirl refuses it leaves that binary alone and
  says the login item is still there, rather than leaving a login item pointing at a program that is
  gone.

## Installing or upgrading

The installer is the same one command, and it is safe to run over an existing install: it verifies
every download against the sha256 published beside it, replaces the app, and replaces an older daemon
with this release's.

    curl -fsSL https://raw.githubusercontent.com/guruor/whirl-ui/v0.2.3/install.sh | sh

The app is ad-hoc signed, not notarized, so the first launch after an upgrade asks for the one
Gatekeeper approval that every unsigned build needs. The installer clears the quarantine flag so no
second approval is asked for. `uninstall.sh` removes what was installed and leaves the daemon's own
state alone.

The daemon pin is unchanged at `v0.2.1`, the newest published daemon release. `whirl` and `whirl-ui`
release independently, and the pin names the daemon release this app is built and tested against.
