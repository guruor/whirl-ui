# whirl-ui v0.2.1

Whirl is a lightweight tray frontend for the [whirl](https://github.com/guruor/whirl) wallpaper daemon.
The daemon is headless: it owns the wallpaper, the rotation, the sources and every piece of state, and
this app is a client of it. It puts the daemon on the menu bar, where the rows show what the daemon
reports and send the daemon's own verbs, and **Settings…** opens a window over the daemon's effective
plan. The app writes no state file, sets no wallpaper itself, and starts no process of its own.

This release is **macOS only**: Apple silicon, macOS 13 or later.

## Which build this is

The release carries one archive, built from the tagged commit by
[`.github/workflows/release.yml`](../../.github/workflows/release.yml):

    Whirl-0.2.1.zip          Whirl.app, the app bundle, at the archive's root
    Whirl-0.2.1.zip.sha256   the archive's sha256, published beside it

The version is the tag: `v0.2.1`, with the leading `v` stripped by `scripts/make-bundle.sh`.

## What changed since v0.2.0

Every change here came out of using the released build on a real machine, which is why the list reads
the way it does.

- **The app finds the daemon the installer installed.** It resolves `whirl` from the installer's
  receipt first, then its own prefix and `PATH`, and it names the copy it ran when a verb cannot be
  started. A build launched from Finder used to inherit a `PATH` without `~/.local/bin` and report
  that `whirl` was not in `PATH`, while the daemon sat exactly where the installer had put it. This is
  the reason the menu bar could not start or stop the daemon at all.
- **The installer installs the app and the daemon as one release.** It reads the daemon's own version
  before deciding: an older daemon is replaced and it says so, an equal one is reused, a newer one is
  left alone and it says so. A new app could previously sit on a daemon from the previous release for
  as long as the daemon kept running.
- **The status follows the daemon, not the last thing the app did.** Pausing used to leave the app
  showing connected, and a daemon stopped from a shell was not noticed. Now one view feeds the tray
  mark, the menu rows and the settings window: `pause` and `resume` re-read the daemon's state on the
  connection that performed the verb, `start` and quitting read on a connection of their own, and the
  app watches its own socket path so a daemon that stops answering takes the view offline within a
  tick.
- **The settings window's daemon line carries the paused state.** It says `whirl is paused` rather
  than `whirl is running`, and a paused daemon is no longer drawn as a failure in the panes that show
  one.
- **Every way out of the app runs the same quit flow.** `⌘Q` is answered by AppKit rather than by the
  app, so it used to bypass the question about stopping the daemon and leave it running with nothing
  said. AppKit's terminate is now routed into the app's own quit flow, question and remembered answer
  included. The settings window's close button still only hides the window.
- **The quit flow no longer asks about a daemon that is not there.** With no daemon answering and
  nothing remembered, quitting asks nothing, prints what it saw and runs no stop, instead of asking
  whether to stop a daemon that is not running.
- **The client's daemon tests check the shape of the answer** rather than a pinned version number, so
  the workspace suite is green on a machine whose installed daemon is current instead of failing with
  an error that looked like a real one.
- **Design, not implementation:** [`docs/updates.md`](../updates.md) records how Whirl should update
  itself and the daemon it needs. Nothing in this release performs an update.

## Installing or upgrading

The installer is the same one command, and it is safe to run over an existing install: it verifies
every download against the sha256 published beside it, replaces the app, and replaces an older daemon
with this release's.

    curl -fsSL https://raw.githubusercontent.com/guruor/whirl-ui/v0.2.1/install.sh | sh

The app is ad-hoc signed, not notarized, so the first launch after an upgrade asks for the one
Gatekeeper approval that every unsigned build needs. The installer clears the quarantine flag so no
second approval is asked for. `uninstall.sh` removes what was installed and leaves the daemon's own
state alone.
